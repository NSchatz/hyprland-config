# Helper scripts (cross-cutting registry)

Surfaces that ship a config referencing shell scripts (eww widgets, hyprpanel `custom/*`, dash
modules) need those scripts to actually exist on disk, or the surface renders empty / errors at
runtime. Defect #10 (eww widgets reference `scripts/sysinfo` / `audio` / `player` / `toggles`
but the plugin never generates them) is the recurring shape.

**Every surface that needs runtime helper scripts declares them here.** Scripts ship verbatim
under `assets/scripts/<surface>/<name>.sh`, the installer copies them to
`~/.config/<app>/scripts/<name>.sh` (or `~/.config/hypr/scripts/<name>.sh` for hypr-local
helpers), and `install.sh` chmod-s them `0755`.

## Rules for writers

1. **A surface that ships a script declares it here, ships the file under
   `assets/scripts/<surface>/`, and the installer copies it.** Without a row here the file
   never gets staged.
2. **Scripts ship verbatim.** No `{{var}}` substitution at copy-time. If a script needs a
   palette color or a font, the script reads `~/.config/hypr-rice/palette.conf` at runtime via
   POSIX shell parsing (the file is `KEY=hex` lines).
3. **install.sh emits one `chmod +x` per script.** The rice installer's "copy helper scripts"
   block walks this registry; missing a script logs a warning and continues.
4. **Scripts written in POSIX shell unless they need richer parsing** — eww's `audio` /
   `sysinfo` / `player` / `toggles` are POSIX-sh with `awk`/`sed`; the `keybind-cheatsheet`
   uses `jq` because it parses `hyprctl binds -j`.

## What "ships verbatim" means for the runtime/generation split

Helper scripts run **after** the install batch, when their runtime deps (`wpctl`, `jq`,
`playerctl`, …) have landed. Scripts may freely use `jq` and any binary the install batch
landed; the *interview-time* tooling (`record-answer.py`, the writer agents) may not depend on
anything outside the prerequisite micro-batch (Python stdlib only — see `_interview-protocol.md`).

## Cross-references

- `components/widgets/template.md` — references `eww/scripts/{sysinfo,audio,player,toggles}` in
  the example yuck. The writer copies them from `assets/scripts/eww/`.
- `components/utilities/template.md` — every utility script row maps to a copy step under
  `hypr/scripts/`.
- `scripts/render-templates.sh` — generates `restore-theme.sh` (per-engine body).
- `agents/hyprland-package-installer.md` — runs `install.sh`, which contains the script-copy +
  chmod block emitted from this registry.
