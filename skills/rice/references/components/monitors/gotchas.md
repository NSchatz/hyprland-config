# monitors — gotchas

## Fractional scale needs three coordinated fixes

When the user pins a non-integer `scale` (e.g. `1.5`, `1.6`, `1.75`), three things must land
together or XWayland/GTK apps render blurry or wrong-sized. Skipping any one of them produces
the exact "fractional scaling is broken" complaint from real-world omarchy builds.

1. **The monitor line itself** (this component):
   ```ini
   monitor = eDP-1, preferred, auto, 1.5
   ```
2. **`env = GDK_SCALE,N`** — emitted by `../env/`. `N` is the **integer ceiling** of the
   fractional value (`1.5` → `2`, `1.25` → `2`, `2.0` → `2`). The `env` component reads
   `monitors.scaling` and gates on `!= 1.0`.
3. **`xwayland { force_zero_scaling = true }`** — emitted into the Hyprland top-level template by
   the writer that owns `hyprland.conf` (see `../keybinds/template.md`). Without it, XWayland apps
   pick up the wrong DPI and render at the wrong size, then get bilinearly upscaled (the
   "everything is fuzzy" symptom).

The flag for "we pinned a fractional scale" is `monitors.scaling != 1.0`. Every downstream
writer keys off that single value, not off iterating `monitors.list[*].scale`.

## Use detected names, not placeholders

`hyprctl monitors` is authoritative — its `Monitor <name>` lines are the names Hyprland accepts in
`monitor = NAME, ...`. The interview should pre-fill the option list with detected names. Only
fall back to `DP-1` / `HDMI-A-1` / `eDP-1` when detection fails (e.g. the user is interviewing
from a TTY or before Hyprland has been started once), and when you do, add a comment line in
`monitors.conf` telling the user to verify:

```ini
# TODO: placeholder names — verify with `hyprctl monitors` and adjust.
monitor = DP-1, 2560x1440@144, 0x0, 1
```

A wrong monitor name **silently no-ops**: the line parses, Hyprland never matches it to a real
output, and the catch-all `monitor = , preferred, auto, 1` ends up driving the display. Users
report this as "my config has no effect" — the template did its job, the name was just wrong.

## `desc:` strings must match `hyprctl monitors` verbatim

For dock/undock (1d) the `desc:` form is the right answer, but the string after `desc:` has to
match the output's "description" field exactly — vendor + model + a serial-ish tail. Trim only
trailing whitespace; do **not** abbreviate. If you only have part of the description, prefix-match
works (`desc:Dell Inc. DELL U2720Q` matches the full string) but the validator can't verify it,
so prefer the full description.

## kanshi / shikane — name the tool, don't author its config

Hyprland has no first-class output-profile system. For hotplug auto-switch the user runs `kanshi`
(Wayland) or `shikane` (a newer alternative). Both live in this component's `packages.md`. Their
configs (`~/.config/kanshi/config`, `~/.config/shikane/config.toml`) **are not generated by the
rice engine** — they're per-laptop and live outside the palette/template story. The interview's
job in 1d is to (a) emit the `desc:` rules so manual hotplug works, and (b) name the daemon so
the package gets installed and the user knows what to configure.

If the user has the daemon installed already (detection flag `HAVE_kanshi=1` or `HAVE_shikane=1`),
the writer drops a `# kanshi/shikane detected — config it at ~/.config/kanshi/config` comment at
the top of `monitors.conf`. Don't write the daemon config.

## `auto` scale vs an explicit number

`monitor = , preferred, auto, auto` (the shipped Hyprland default) lets Hyprland choose **including
fractional** values. That's fine for "I don't care," but it makes the fractional-scaling-fix block
above ambiguous — we don't know what `N` should be for `GDK_SCALE`. **Rule:** if the user picked
`single-auto` in 1a and `No, scale 1` in 1b, emit literal `auto` and skip the env/xwayland fixes.
If the user picked any explicit fractional scale, emit the number (not `auto`) and emit all three
fixes.

## Version branch — `windowrule` block form

The smart-gaps block (1e) uses the 0.53+ `windowrule { … }` block form. On targets `< 0.53`, fall
back to the legacy line form:

```ini
windowrule = bordersize 0, onworkspace:w[tv1]
windowrule = rounding 0,   onworkspace:w[tv1]
```

See `../../_shared/version-matrix.md` for the full cliff table and the detection invocation.
