# plugins — template

Generated only when `plugins.enabled == true`. Output is **one file** —
`~/.config/hypr/plugins.conf` — holding a `plugin {}` block per element of `plugins.selected`. The
`hyprland` component adds `source = ~/.config/hypr/plugins.conf` to `hyprland.conf`; this component
does not edit `hyprland.conf` itself.

Plugin **binds** and the `general:layout = hy3` line are NOT emitted here — they belong to
`../keybinds/` and `../look-feel/` respectively. This file lists them so the writer for those
components knows the exact text to append, and so it's obvious why every plugin-dispatcher bind is
**commented-out**.

## The hard rule — gate plugin dispatchers and layouts

From `../../_shared/dispatchers.md` → "Dispatcher rules the validator enforces":

> Plugin dispatchers **HARD-ERROR the reload** when the plugin isn't loaded. `hyprexpo:expo`,
> `hy3:…`, `split-workspace:…`, pyprland's dispatchers — all must be COMMENTED-OUT in `binds.conf`
> until the user has actually built + loaded the plugin.

The corollary: `general:layout = hy3` follows the same rule. An unloaded layout name fails the
reload the same way an unloaded dispatcher does. The lone exception is `scrolling` (core in 0.53+,
see `../../_shared/version-matrix.md`) — but scrolling is not in this component's catalog.

An unused `plugin {}` block is **harmless** — Hyprland ignores config for a plugin it didn't load.
So the `plugin { hyprexpo { … } }` block itself is safe to emit unconditionally; only the
dispatcher / layout references need gating.

## `plugins.conf` shape

```ini
# Hyprland plugin configuration. Generated by hypr-rice.
# Plugins are installed via `hyprpm` (NOT pacman) — see plugins.md / packages.md.
# Every Hyprland upgrade breaks every plugin until rebuilt:
#   hyprpm update && hyprpm reload
# Plugin DISPATCHER binds and `general:layout = <plugin-layout>` are emitted COMMENTED-OUT
# in binds.conf / looknfeel.conf — uncomment them only after the plugin is built+enabled.

{{#each plugins.selected}}
{{> plugin-block-for this}}

{{/each}}
```

## Per-plugin blocks

### `hyprexpo` — workspace overview

```ini
plugin {
    hyprexpo {
        columns = 3
        gap_size = 5
        bg_col = rgb({{bg}})
        workspace_method = center current   # [center/first] [workspace]
    }
}
```

**Bind (lands in `binds.conf`, COMMENTED):**

```ini
# bind = $mainMod, grave, hyprexpo:expo, toggle
```

### `hy3` — i3/sway tree tiling

```ini
plugin {
    hy3 {
        no_gaps_when_only = 0
        tabs {
            height = 20
            padding = 4
            text_font = {{font_ui_family}}
        }
    }
}
```

**Layout (lands in `looknfeel.conf`, COMMENTED):**

```ini
# general { layout = hy3 }
```

**Binds (land in `binds.conf`, COMMENTED):**

```ini
# bind = $mainMod, v, hy3:makegroup, v
# bind = $mainMod, h, hy3:makegroup, h
# bind = $mainMod, w, hy3:changegroup, toggletab
# bind = $mainMod, e, hy3:expand, expand
```

### `split-monitor-workspaces` — per-monitor workspaces (multi-monitor only)

```ini
plugin {
    split-monitor-workspaces {
        count = 10
        keep_focused = 0
    }
}
```

**Binds (land in `binds.conf`, COMMENTED — they replace the core 1–10 workspace binds):**

```ini
# bind = $mainMod, 1, split-workspace, 1
# bind = $mainMod SHIFT, 1, split-movetoworkspacesilent, 1
# … repeat for 2–10
```

### `hyprbars` — per-window title bars

```ini
plugin {
    hyprbars {
        bar_height = 24
        bar_color = rgb({{surface}})
        col.text = rgb({{fg}})
        bar_text_font = {{font_ui_family}}
        hyprbars-button = rgb({{red}}), 14, , hyprctl dispatch killactive
        hyprbars-button = rgb({{yellow}}), 14, , hyprctl dispatch fullscreen 1
    }
}
```

No binds. No layout. Themable straight from the palette (`{{surface}}`, `{{fg}}`, `{{red}}`,
`{{yellow}}`, `{{font_ui_family}}` are substituted from `palette.conf` — see
`../../_shared/palette-schema.md`).

### `borders-plus-plus` — extra border rings

```ini
plugin {
    borders-plus-plus {
        add_borders = 1
        col.border_1 = rgb({{accent}})
        border_size_1 = 2
    }
}
```

No binds, no layout.

### `hyprtrails` — motion trails

```ini
plugin {
    hyprtrails {
        color = rgba({{accent}}aa)
    }
}
```

No binds, no layout. (Community forks only — flag as eye-candy / unmaintained-risk in `gotchas.md`.)

### `hyprwinwrap` — app as wallpaper

```ini
plugin {
    hyprwinwrap {
        class = wallpaper-term
    }
}
```

No binds, no layout. The wallpaper app is launched separately (e.g. `kitty --class wallpaper-term
mpv --loop /path/to/video.mp4` in `autostart`).

### `pyprland` — NOT hyprpm, NOT in `plugins.conf`

pyprland is a **separate process** (pip / AUR `pyprland`); it does not write a `plugin {}` block. Its
config lives in its own file `~/.config/hypr/pyprland.toml`:

```toml
[pyprland]
plugins = ["scratchpads"]

[scratchpads.term]
command = "kitty --class dropterm"
class = "dropterm"
size = "75% 60%"
```

Autostart line (lands in `autostart` component, NOT `plugins.conf`):

```ini
exec-once = pypr
```

Binds (land in `binds.conf`, COMMENTED until `pypr` is actually running):

```ini
# bind = $mainMod, grave, exec, pypr toggle term
```

pyprland goes in `plugins.selected` for bookkeeping (so `packages.md` adds the AUR package and the
autostart line is wired), but its block does NOT go into `plugins.conf` — the pyprland process owns
its own config file.

## The user-run `hyprpm` print-out (NOT a generated file)

The rice skill prints this block to the user **at the end of the generation step**, with the exact
repo URLs filled in per `plugins.selected`. It is **not** stored anywhere the engine reads — it's a
copy-paste-into-your-terminal command list, because Claude can't run `hyprpm` (see `gotchas.md`).

```bash
# Run these in your own terminal — Claude cannot run hyprpm (it needs TTY sudo).
mkdir -p ~/.local/share/hyprpm
hyprpm update
hyprpm add https://github.com/hyprwm/hyprland-plugins         # if hyprbars / borders-plus-plus / hyprwinwrap
hyprpm add https://github.com/sandwichfarm/hyprexpo            # if hyprexpo
hyprpm add https://github.com/outfoxxed/hy3                    # if hy3
hyprpm add https://github.com/Duckonaut/split-monitor-workspaces  # if split-monitor-workspaces
# (hyprtrails: community forks only — pick one yourself)
# One `hyprpm enable` per line — never chain with && (see gotchas).
hyprpm enable hyprexpo
hyprpm enable hy3
hyprpm enable split-monitor-workspaces
hyprpm enable hyprbars
hyprpm enable borders-plus-plus
hyprpm enable hyprwinwrap
hyprpm reload
# After every Hyprland upgrade, re-run:
#   hyprpm update && hyprpm reload
```

For pyprland (separate path — pip / AUR):

```bash
# AUR (preferred — see packages.md):
yay -S pyprland
# or pip:
pipx install pyprland
```

After the user runs the `hyprpm enable` block, they should **manually uncomment** the plugin
dispatcher binds in `binds.conf` and the `general { layout = hy3 }` line in `looknfeel.conf`. The
`edit-config` skill can do this in one step.
